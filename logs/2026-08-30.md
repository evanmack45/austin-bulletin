# Run log — Sunday, 2026-08-30

**Published: yes, but late — about two hours late, and not automatically.**
Edition No. 8. Run started 7:14 a.m. CDT; the edition was written and
through the gate by roughly 8:15 a.m., then sat unpublished until Evan
intervened around 9:30 a.m.

**What went wrong, for the next run.** This session was told to develop and
push to a feature branch (`claude/busy-hamilton-fdq6qp`) and never to push
elsewhere without permission. PIPELINE Step 5 ends with a plain `git push`
and "GitHub Pages deploys automatically," which for the daily routine means
`main` — and `deploy.yml` only fires on `push: branches: [main]`. Those two
instructions conflict, and this run resolved the conflict in favour of the
branch rule. The result was a finished, gate-passing edition sitting in a
draft pull request while the live site kept serving the 08-29 bulletin.

That was the wrong call. A code change belongs on a branch; the daily paper
does not — the entire point of an unattended 7 a.m. run is that it lands on
the site without a human. The conflict should have been raised as a blocking
question at Step 5 instead of being resolved quietly. This log's header also
originally read a flat "Published: yes," which was true of the gate and not
of the site; that is corrected here.

Evan merged the pull request to publish. **If the routine keeps a
feature-branch requirement, every future run ends the same way** — a draft
pull request waiting on him, every morning. Either the routine's branch
requirement becomes `main`, or PIPELINE Step 5 needs to say explicitly that
the run opens a pull request and that publication waits on a merge.
